# LuoLuoTool

> 自用《桃源深处有人家》日常挂机自动化工具（Windows 桌面）

当前版本：**0.1.0**（来自 `src/luoluotool/__init__.py`）。

## 1. 这是什么 / 明确不做什么

**这是什么**：一个跑在 Windows 上的**单机**桌面挂机工具。界面用 PySide6（Qt 6），用 OpenCV 模板匹配在游戏窗口客户区里「按图找点」，再通过系统级输入注入（`SendInput`）真实移动鼠标、模拟按键去点游戏。配置就是本地一个 JSON 文件，没有数据库、没有账号体系、程序不做网络请求。

**给谁用**：只有一个人——作者自己。给自己机器上的《桃源深处有人家》跑日常挂机用。

> ⚠️ **风险提示（先看这一句）**：本工具会真实操作你的鼠标键盘，自动化操作**可能违反游戏用户协议、存在封号风险**，真实模式下执行期间还会抢走前台窗口。**仅限个人学习自用，风险自负**；完整声明见第 13 节。

**明确不做什么**（等同红线，见 `PROJECT_SPEC.md` §4 与 `AGENTS.md` §3）：

- **不读、不改游戏进程内存**；**不拦截 / 伪造 / 重放网络封包**；不破解客户端、不绕过游戏更新、不篡改或屏蔽反作弊组件；
- **不收集账号、密码、token、设备指纹**，程序不要求登录；
- **不上传**日志 / 配置 / 截图等任何本地数据；
- **不做通知、推送、上报功能**（程序里没有这类代码，也没有为它预留开关或字段）；
- **不做多开批量打金**（不做多实例协调、不做账号矩阵）；**不规避未成年人防沉迷**。

## 4. 安装

### 4.1 源码方式（开发 / 折腾用）

```powershell
cd <仓库路径>                      # 路径按你自己的改
python -m venv .venv                                 # 创建虚拟环境
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt   # -r requirements.txt 与 -e . 已包含在内
```

依赖很小：`requirements.txt` 只有 PySide6、pywin32、numpy、opencv-python-headless；`requirements-dev.txt` 额外加 pytest、pytest-cov、pyinstaller。`opencv-python-headless` 会让打包体积增加约 60–70 MB，这是识别功能的代价（`requirements.txt` 里有理由注释）。

### 4.2 打包产物方式（不装 Python 也能跑）

1. 把**整个** `dist\LuoLuoTool\` 目录拷到目标机器（**不要只拷 exe**，one-dir 依赖同目录的 `_internal`）；
2. 先给该目录加杀软白名单（见 FAQ Q5）；
3. 双击 `LuoLuoTool.exe`。首次运行会在**该目录下**自动生成 `user_data\`（配置）与 `logs\`（日志）。

重新构建产物：

```powershell
# 可选参数：-SkipInstall（依赖已装好）、-SkipTests（仅排错用，正式打包不要跳过）
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

## 5. 快速开始（从零到跑起来）

```powershell
cd <仓库路径>

# ① 预期输出一行：luoluotool 0.1.0
.\.venv\Scripts\python.exe -m luoluotool --version

# ② 预期输出 OK；配置文件还不存在时会打印「OK（配置文件不存在：<路径>，首次启动将生成默认值）」
.\.venv\Scripts\python.exe -m luoluotool --validate-config

# ③ 打开界面（不带任何参数默认就是 GUI）
.\.venv\Scripts\python.exe -m luoluotool
```

打开界面之后的最小路径：

1. 把游戏**窗口化**跑起来并保持在屏幕上；
2. （推荐）提示权限不足时，点设置页的「以管理员身份重启」，在 UAC 里同意；
3. 设置页勾上「**开发者调试**」，顶部多出「开发者调试」页签；
4. 到该页的「图片识别匹配测试」里点「添加图片…」选一张识别图，点「图片识别匹配测试」→ 会打印命中位置的**客户区坐标**，用来确认「找图 → 坐标」这条链路是通的；
5. 回主界面点「**启动**」。注意**默认是真实模式**（`dry_run` 出厂默认 `false`），会弹「确认真实模式」对话框（默认按钮是「否」），确认后才真的操作游戏；
6. 运行中随时按 **F8** 急停，或点界面「停止」。

不想动真实鼠标键盘时，在开发者调试页勾「**干跑模式**」——只写日志、零真实输入。

### 6.2 日常任务页怎么配

**总开关与循环**：「启用日常任务」是总开关，**关着时日常任务组一个任务都不入队**（卡订单 / 功能三 / 功能四不受影响；关着总开关却勾了任务时启动日志会明确警告）。「**按固定间隔循环**」不勾就只跑一轮；勾了才在每轮结束后等「**循环间隔（分钟）**」（界面 1–720 分钟，配置里存秒 `loop.interval_seconds`）。只有你真的动那个数字框才会写回配置。

**三个生产建筑分组**（鸡舍 / 土地 / 水产养殖，结构相同）：

- 「**所在岛屿编号**」：下拉选 1–10；
- 「**选择图片…**」：默认打开 `assets/templates/`，只收 png / jpg / jpeg / bmp / webp；**可一次选多张**（最多 10 张，重复路径自动去重，超出部分只取前 10 张并提示），选中的这批**替换**该建筑原来那一组；选图即校验——纯色图直接拒收并提示换一张，「辨识度偏低」只提示不拦；
- 「**截取游戏画面**」：先把游戏窗口切到前台（等约 0.4 s，避免截到本工具自己）→ 截客户区 → 弹出**框选窗口** → 只保存你框住的那块到 `assets/anchors/`（文件名形如 `鸡舍_岛屿1_<时间戳>.png`），并**追加**到已选图片末尾；已在列表里的不重复加，满 10 张会拒绝并提示先移除一张；
- **缩略图条**（横排小图、左上角标序号、选中那格高亮）：**点一格**＝下方大图换成那张；**双击**（或双击大图）＝工具内放大预览；每格**右上角有 ×**（悬停变红底白叉、提示「移除第 N 张」，点它只删那一张、不改当前选中项）；缩略图条右侧的「**清空全部**」按钮＝一次清掉这一组（没图时灰掉）；右键缩略图 / 大图＝同样的「移除第 N 张」/「清空全部」；
- **删除会连磁盘文件一起删**：任何移除入口都**先弹一次确认框（默认按钮是「取消」，回车不会删东西）**，确认后才动手；只删工具管理的 `assets/templates/`、`assets/anchors/` 里的图片，仓库外的图片（例如从桌面选的）**只从列表移除**，同一张图还被别的建筑引用时**不删文件**、只在状态栏说明原因；
- **删除不可撤销**：`assets/templates/` 里入库的图片可以用 git 恢复，`assets/anchors/` 里的框选产物不入库、**删了就没了**；
- 参考图路径按**相对仓库根**存进配置；图片被删 / 改名时只提示并清掉缩略图，**不会悄悄改配置**；
- 「**产物制造**」：「自动识别存量最少的产物并优先制造」目前**只读**（值照常入库）。

> 页面上「岛屿编号参考图」与「示例图片」两块目前还是**虚线占位框**（写着「临时占位」）。目前**不会**自动去寻找这些建筑——三组配置是为下一批「日常任务自动流程」准备的。

### 6.3 开发者调试页怎么开 / 里面有什么

在**设置页**勾选「**开发者调试（在顶部显示「开发者调试」标签页）**」，顶部立刻多出该页签；取消勾选会移除页签并中断正在跑的调试动作。**未开启时该页所有选项一律不生效**（整页禁用，干跑开关与还原光标开关的改动不会写进配置）。

页内可做：**干跑模式**开关、**还原光标**开关（点击 / 滑动后是否把真实鼠标移回原位）、**窗口诊断**（找游戏窗口并截图到 `user_data/debug/`）、**布局测量**（检查各页签高度是否互相影响）、**图片识别匹配测试**（模板列表可多选添加 / 移除 / 清空，阈值默认 0.85，最多列出默认 20，「识别成功时保存带框截图」，「框选截图生成模板」）、**鼠标单点 / 连点 / 屏幕滑动 / 键盘测试**（单点与连点都带「点击时长」，默认 40 ms）。

调试测试与正式任务**互斥**（任务在跑时不能做输入测试，反之亦然）；测试放后台线程、执行期间按钮禁用，可用「停止」或 F8 中断。

### 6.4 框选弹窗（生成模板 / 参考图时弹出）

拖出选区后还能继续改：拖**选区内部**＝整体移动，拖**四角 / 四边手柄**＝改大小（按住 **Alt** 为中心对称缩放），**选区外**重拖＝重新框选，**空格拖拽 / 右键拖拽**＝移动选区，**方向键**＝挪 1 像素（Shift＝10 像素，Ctrl＝该边外扩 1 像素，Ctrl+Shift＝内收 1 像素），**双击**＝清空重来，**Esc**＝撤销这次拖拽 / 清空。**滚轮**以鼠标为中心缩放，**中键拖拽**或**空格 + 拖拽**平移画面，下面的**滑条**左右拉改缩放（100%＝整图适配，最高 800%；**双击滑条**＝1:1 显示），旁边「**重置**」＝回初始状态（缩放复位 + 清空选区）；鼠标旁有 6 倍**放大镜**，信息行显示「选区尺寸 / 可辨识度 / 缩放倍率 / 鼠标客户区坐标」。

- **保存前会查可辨识度**：选区几乎是纯色时**不写文件也不关窗口**，直接说明原因让你换一块有纹理 / 数字的区域（这种模板存下来只会在画面上到处误匹配）；「辨识度偏低」只提示、仍可保存。
- **「在本图试识别」**：把当前选区当模板，当场在这张截图上匹配一次，回答「这块区域在这张图上是不是独一无二」。结论只限定在 **1:1 匹配**——正式识别还会搜缩放版本、阈值也可能更低，所以它只是参考、不是保证。
- 「**保存为模板**」只保存你**手动框住**的那块区域（绝不把整屏截图当模板存下来）；没有有效选区时不写文件、也不关窗口。

### 6.5 F8 急停 与 干跑模式

- **F8 急停**：默认热键 **F8**，可在设置页改成 F9–F12，点「保存」后立即生效。急停会中断任务线程、调试测试、截图与参考图解码；停止请求发出后 500 ms 内停止动作序列，任何退出路径都会释放按键 / 左键（不会把鼠标卡在按下状态）。热键可能被别的程序占用——**注册失败时状态栏与设置页会红字提示**，这种情况下「停止」按钮是你唯一的中断手段，务必先确认它能点。
- **干跑（dry-run）模式**＝**只写日志、零真实输入**（点击 / 滑动照样做越界校验，但不会真的动鼠标键盘）。**注意默认值**：出厂 `automation.dry_run = false`，也就是**默认就是真实模式**，首次启动就已经是真实模式；因此真实模式启动前**每次都会弹确认框**。切干跑的入口在开发者调试页（需先打开「开发者调试」）。单元测试恒走干跑，绝不产生真实输入。

## 7. 配置说明

### 7.1 位置与生成时机

| 场景 | 配置文件位置 |
|---|---|

### 7.3 版本迁移、备份与损坏恢复

- **schema 版本**：当前 `SCHEMA_VERSION = 11`。旧配置在加载时**自动迁移**（`setdefault` 补齐新字段，不动你原有字段值），迁移后写回并记日志。
- **磁盘版本比程序新**：程序**只读启动**（按默认值运行、**不修改文件**）+ WARNING；此时保存会先把旧文件备份成 `config.json.bak-v<磁盘版本>-<时间戳>`。
- **保存前先校验**：配置不合法时**拒绝落盘**并弹窗说明原因，磁盘上的旧文件保持原样（避免写出「自己下次读不回来」的配置）。
- **损坏自动恢复**：JSON 解析失败 / 迁移失败 / 校验失败时，把坏文件备份为 `config.json.bak-<时间戳>`，写回默认配置并记 WARNING。发现设置「变回默认」时，先去 `user_data/` 看有没有这些 `.bak-*` 文件。
- 备份文件与 `config.json` 一样**不入库**（见 `.gitignore`）。

## 8. 命令行参数

入口：`python -m luoluotool`（源码方式）或 `LuoLuoTool.exe`（打包产物）。**不带任何参数＝打开 GUI**。参数逐个对应 `src/luoluotool/__main__.py`：

| 参数 | 作用 | 示例 |
|---|---|---|
| `--version` | 打印版本号后退出（退出码 0） | `python -m luoluotool --version` |
| `--config PATH` | 指定配置路径（默认 `user_data/config.json`） | `python -m luoluotool --config D:\tmp\c.json` |
| `--validate-config` | 校验配置：通过打印 `OK`（退出码 0），不合法逐条打印错误（退出码 1）；文件不存在也打印 `OK（配置文件不存在：…）` 并返回 0 | `python -m luoluotool --validate-config` |
| `--smoke-gui` | 离屏创建主窗口后立即退出，日志含「离屏冒烟完成」 | `python -m luoluotool --smoke-gui` |
| `--measure-layout` | 离屏测量各页签布局占用并打印报告（末行 `[OK]`＝「挂载 / 卸载开发者调试页不改变任何高度」；有问题返回 1） | `python -m luoluotool --measure-layout` |
| `--recognize IMAGE [IMAGE ...]` | 在当前游戏窗口客户区里查找这些图片（模板匹配），打印命中位置的客户区坐标；可给多张，按顺序尝试、**第一张达到阈值的直接采用** | `python -m luoluotool --recognize assets\templates\鸡舍_白天.png` |
| `--max-results N` | 一张模板最多列出多少处命中（默认 20） | `... --recognize a.png --max-results 5` |
| `--threshold 0-1` | 识别阈值，越高越严格（默认 0.85；必须 >0 且 ≤1，否则退出码 2） | `... --recognize a.png --threshold 0.9` |
| `--no-annotate` | 识别时不保存带框截图（默认跟随配置 `automation.save_vision_annotations`） | `... --recognize a.png --no-annotate` |
| `--no-scale` | 只按原始尺寸匹配（默认两档多尺度：先 0.3x–2.0x，找不到再扩到 0.3x–4.0x） | `... --recognize a.png --no-scale` |

**退出码**：`--recognize` 为 0 命中 / 1 未命中或识别失败 / 2 参数非法；`--validate-config` 与 `--measure-layout` 为 0 通过 / 1 有问题；GUI 与 `--smoke-gui` 正常退出为 0。

## 11. 常见问题（FAQ）

**Q1 找不到游戏窗口 / 提示「未找到标题含“…”的窗口」**：① 确认游戏已启动并窗口化显示（最小化 / 不可见都不行）；② 确认窗口标题里真含有 `automation.window_title_keyword` 的值（默认「桃源深处有人家」），改过标题或用了别的启动器时把它改成标题里稳定存在的一段；③ 游戏以管理员运行而本工具不是时系统会拒绝置前与截图，按提示点「以管理员身份重启」后重试；④ 多个窗口同时匹配时只用第一个并写 WARNING，关掉多余的那个。

**Q2 截图是黑帧 / 明明有目标却报「未识别到目标」**：本作是 GPU 渲染 + 管理员运行，**`PrintWindow` 会返回纯黑帧**，程序会自动回退（窗口 DC BitBlt → 屏幕 BitBlt），而屏幕 BitBlt **只在窗口处于前台时**才用（否则会截到被遮挡的内容）。所以：① 让游戏窗口保持在最前面，别让其它窗口盖住它；② 以管理员身份运行本工具；③ 用调试页「窗口诊断」存一张图到 `user_data/debug/` 肉眼确认不是黑的——黑帧不会被当成「没识别到目标」；④ 确认窗口没有最小化。

**Q3 识别出来的坐标整体偏下**：这是一个**修过的历史 bug**（取景原点错用窗口左上角而非客户区左上角，实测偏 37 px；现在统一走 `automation/window.client_area_offset`）。若仍整体偏移：① 确认手里的版本包含该修复并重新构建；② 用调试页「窗口诊断」截图，核对画面左上是否等于 `ClientToScreen(0,0)`；③ 按 `BUG_HUNT_GUIDE.md` 的三条实机探针（窗口几何 + 取景原点、逐条取景路径量偏移、坐标端到端交叉验证）定位是哪条取景路径不对。

**Q4 点了没反应（日志却写着「完成」）**：① **先确认不是干跑**——干跑只写日志、完全不动鼠标键盘（开关在开发者调试页）；② 真实模式下每次点击前会把游戏窗口置顶 / 置前，做不到就**不点击**并写 WARNING，搜日志里有没有「不在游戏窗口内」「已跳过本次点击」「光标偏差」等记录；③ **点击坐标必须是客户区坐标**，越界一律跳过，别拿屏幕坐标去填；④ 日志里若记录实测光标与目标偏差 > 4 px，说明这次点击被主动跳过（避免点在错误位置误触别的按钮）；⑤ **不要把「点击后把真实鼠标移回原位」关掉来求快**——光标一次跳回会让游戏在处理这次点击的那一帧看到「指针已不在窗口内」而丢弃点击，程序为此专门做了「延迟 + 分帧小步移回」；同理不要为了快去调小点击时间线上的等待常量；⑥ 用调试页「鼠标单点测试」用同一坐标点一次，能点动说明输入链路是通的，问题在识别坐标或游戏状态。

**Q5 打包出来的 exe 被杀软误报 / 直接被删**：PyInstaller 打的包常被 Windows Defender 或国产杀软按 bootloader 特征误报，**不是病毒**。二选一：① Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 排除项 → 添加排除项 → **文件夹** → 选中 `…\dist\LuoLuoTool`；② 或把整个 `dist\LuoLuoTool` 加入所用杀软的信任区后再运行。已被隔离的话，先从隔离区恢复并加白，再重新构建。本工具**未做代码签名**，首次运行可能出现 SmartScreen 提示。

**Q6 配置被重置成默认了**：① 看 `user_data/` 下有没有 `config.json.bak-<时间戳>`——有就说明**文件被判损坏**（JSON 语法错 / 迁移失败 / 校验不通过），程序备份后用默认值恢复，日志里写了原因；② 有 `config.json.bak-v<版本>-<时间戳>` 说明磁盘配置的 schema 版本比程序新（降级运行不会静默吃掉新版配置，会先备份）；③ 手工编辑过配置时用 `python -m luoluotool --validate-config` 逐条看错误；④ 界面上「恢复默认」只改内存、「重新加载」会丢弃未保存改动，注意别误点。

**Q7 图片识别不到（换分辨率 / 缩放后失效）**：① 默认已开启**多尺度两档搜索**（先 0.3x–2.0x，找不到再扩到 0.3x–4.0x），不要用 `--no-scale`（只按原始尺寸匹配）；② 把阈值调低一点（`--threshold` 或调试页阈值，默认 0.85），或换一块纹理更多、更稳定的区域做模板；③ **纯色 / 平坦模板会被直接拒绝**——平坦区域对无纹理模板天然满分（实测一张纯色图在真实画面上刷出 20 处「匹配度 1.000」），模板必须有边界或有文字；④ 极小模板（小于约 40 px）配小缩放时缩放判断可能不准，换大一点的模板；⑤ 命中多处时程序会全部列出（第 1 处为默认使用值），若第 1 处不是你想要的，说明模板不够独特，换一块或用「在本图试识别」先看看有没有重复元素。

**Q8 参考图文件被删掉或改名了**：程序**只提示、不会悄悄改配置**（状态栏给提示、缩略图清空，配置里那条路径原样保留）。处理办法：把文件恢复回原路径 / 原名，或重新用「选择图片…」/「截取游戏画面」选一批（选中的这批会替换该建筑原来那一组）。

**Q9 循环间隔改了没效果 / 只跑了一轮就结束**：① 「**按固定间隔循环**」**不勾就只跑一轮**，先勾上它；② 「启用日常任务」总开关关着时日常任务组一个都不入队，关着却勾了任务时启动日志会警告「已勾选的 N 个日常任务不会执行」；③ 队列里一个任务都没有时程序不执行任何任务并立即结束，这是正常行为；④ 界面按**分钟**填（1–720）、配置里存**秒**；手工把配置改成非整数分钟（如 90 秒）时界面显示最近的分钟数但不回写，只有真的动那个数字框才写回。

**Q10 界面提示「配置未保存」**：保存前会先校验，不合法的值（步数 / 点击数超上限、未知键名等）会被拒绝落盘，磁盘旧文件保持不动并弹窗说明原因。按提示改掉那几项再保存即可——历史上「界面允许填但校验器不接受」会写出自己下次读不回来的配置，最终导致整份配置被重置，所以这里故意收紧。

**Q11 鼠标 / 键盘卡在按下状态**：正常路径不会——长按与滑动**无论正常结束、被急停还是异常退出都会释放按键 / 左键**。真遇到时先按一次 F8 或点「停止」；仍不行就手动按一下对应键或点一下鼠标左键，日志里能看到补发释放的记录。

**Q12 急停热键按了没反应**：看设置页有没有红字提示——热键可能被别的程序占用，注册失败是**看得见**的（状态栏 + 设置页）。换成 F9–F12 后点「保存」，或直接用界面「停止」按钮中断。

## 12. 已知限制与未实现（不遮掩版）

1. **没有真正的日常任务流程**：日常任务页只能配置岛屿编号、参考图与循环参数，**不会**自动去找建筑、也不会自动种地 / 收菜（第 3 批待做）。
2. **卡订单、功能三、功能四只是占位**：进队列后只写「该功能尚未实现真实逻辑（规划中）」+ 每条一轮心跳日志，**不产生任何输入**；「预留开关 1 / 2」无任何行为。
3. **输入会抢前台、会动真鼠标**：每次点击 / 按键前都会把游戏窗口置顶 / 置前，执行期间不宜操作其它软件。
4. **取景依赖窗口可见**：最终兜底是屏幕 BitBlt，窗口被完全遮挡或最小化时取不到画面。
5. **识别耗时**（1920x1052 实测）：1.0x 命中约 1.9 s、1.5x 约 2.3 s、2.0x 约 2.8 s；需要第二档时 2.5x 约 3.9 s、3.5x 约 4.0–4.9 s、4.0x 约 4.4–5.2 s；画面里没有目标（两档都要扫）约 3.8 s。
6. **极小模板 + 小缩放**的缩放判断可能不准（模板匹配的固有限制）。
7. **只保证 100% 缩放 + 单显示器 + 窗口化游戏**；多显示器 / 高 DPI 缩放未适配。
8. **识别参数不落配置**：模板列表、阈值、最多列出只在调试页临时选择。
9. **离线识别（拿识别底图当匹配源）未实现**；`assets/screenshots/` 目录已留。
10. **启动时从远程服务器加载 / 更新配置项未实现**（唯一预留的联网缺口：只拉取不上传、不可用必须降级到本地、默认关闭）。
11. **打包**只做 one-dir，不做 one-file 与安装包、未做代码签名；one-dir 首次启动比开发期慢（一次性解包 + Qt 初始化）。
12. **识别功能让打包体积增加约 60–70 MB**（numpy + opencv-python-headless）。
13. **`automation.click_interval_ms` 与 `automation.post_click_wait_ms` 目前不生效**：两项都已存盘、已校验、设置页也能改，但代码里**还没有运行期消费者**（占位任务用的是每步的 `params.wait_after_ms`）；等「日常任务真实动作流程」接入后才会用上。
14. 当前版本 **0.1.0**，功能按批次推进；以第 2.2 节的「尚未实现」清单为准。
