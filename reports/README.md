# reports/ — 代码审查报告目录

> 本目录存放本项目的**代码审查 / 复审报告**。报告只记录审查结论，**不修改任何代码**。

## 命名规则（用户 2026-09-20 指定）

```
CODE_REVIEW_REPORT_<年月日>_<第几份>.md
```

| 片段 | 含义 | 示例 |
|---|---|---|
| `<年月日>` | 报告出具日期，8 位数字 | `20260920` |
| `<第几份>` | **当天**的第几份报告，从 1 开始 | `1`、`2`、`3` |

示例：`CODE_REVIEW_REPORT_20260920_1.md`（2026-09-20 第 1 份）、`CODE_REVIEW_REPORT_20260920_2.md`（同日第 2 份）；
跨天重新从 `1` 开始计数。**同一份报告一旦出具就不再改名**，后续复审另开新的一份。

## 报告约定

1. **只读**：审查过程不改动任何代码；发现问题只写进报告。
2. **分级**：问题按 `P0`（阻断/数据丢失/安全）→ `P1`（必须修）→ `P2`（应修）→ `P3`（建议）标注，每条给出 `文件:行` 与代码原文。
3. **有证据**：能复现的问题给出复现步骤或实验结论；只靠读代码得出的结论要显式标注「未实机复现」。
4. **可追溯**：报告开头写明基线 `git HEAD`、验收命令实测结果、以及本轮**未覆盖/未能验证**的范围。
5. 新增报告后，把新的一行补进上面的「报告索引」表。
